## Why

Projects contributors and coding agents need documentation that distinguishes the current scaffold from future product behavior. Repository-local instructions and specifications will let the architecture grow from reviewed requirements.

## What Changes

- Add English Projects documentation, architecture guidance, contribution rules, and a practical pull-request template.
- Establish authoritative root and application-scoped instructions plus one focused Projects feature Skill with generated Claude/Copilot mirrors.
- Adopt OpenSpec 1.10.0, documentation linting, public validation scripts, and CI gates.

Non-goals include adding project-management features, routes, persistence, speculative architecture, federation changes, hosting changes, or runtime application changes.

## Capabilities

### New Capabilities

- `agent-ready-projects-development`: Repository instructions, specifications, documentation, and validation for safely growing the Projects remote.

### Modified Capabilities

None.

## Impact

Development dependencies, repository documentation, agent integrations, OpenSpec artifacts, npm scripts, and Firebase workflows change. Runtime scaffold and deployment contracts remain unchanged.
